启动应用
=============

流程目标
^^^^^^^^

帮助用户完成平台最常用的科研计算任务——启动交互式应用（如
``Jupyter Lab``、``Terminal``、``Linux Desktop``、``vscode`` 等）。

进入方式
^^^^^^^^

点击左侧菜单 ``应用列表``，进入应用页面。也可以从工作台 ``快捷操作``
中的 ``应用管理`` 按钮进入。

页面内容
^^^^^^^^

页面顶部是 ``用户配额图表``，显示当前账户的 CPU、GPU、内存使用情况
和配额上限。

页面中部是 ``交互式应用`` 标签页，含应用卡片网格（``Terminal``、
``Jupyter Lab``、``Linux Desktop``、``vscode`` 等）。当前版本不再单
独提供 ``批处理作业`` 标签，如需在后台运行脚本，请直接使用应用卡片
启动应用并在终端内执行。

页面底部是 ``作业列表``，列出当前账号最近产生的作业记录。

.. figure:: /_static/application-list.png
   :alt: 应用列表
   :width: 90%

   应用列表页面，含用户配额图表、应用卡片网格（仅有 ``交互式应用``
   标签）和底部作业列表。


应用卡片网格
^^^^^^^^^^^^

``交互式应用`` 标签的中部是应用卡片网格。**不同应用的卡片格式略有
不同**：

- ``Terminal`` 卡片：只有应用图标、名称和 ``启 动`` 按钮（直接挂接登录节点，无需申请额外资源）。
- 其他应用卡片（如 ``Jupyter Lab`` ``Linux Desktop`` ``vscode``
  ``IceWM`` 等）：包含 ``App`` 类型下拉、``N cpus`` 行（选择 CPU
  数量）、``M gpus`` 行（选择 GPU 数量，部分应用不支持）、``项目组``
  行（选择计费项目组）、``启 动`` / ``关 闭`` 按钮。

.. figure:: /_static/application-cards-with-project-group.png
   :alt: 应用卡片和启动按钮
   :width: 90%

   应用卡片示例。从左到右：``Terminal``（仅 ``启 动`` 按钮）、
   ``Jupyter Lab``、``Linux Desktop``、``vscode``（含 App / cpus /
   gpus / 项目组选择与 ``启 动`` / ``关 闭`` 按钮）。启动非 Terminal
   类应用前，可在卡片的 ``项目组`` 行下拉选择本次任务要计费的项目组，
   例如 ``2026 Summer School``；不选择项目组则个人承担相关计费。

启动流程
^^^^^^^^

1. 在左侧菜单点击 ``应用列表``，进入应用页面。
2. 在应用卡片网格中找到目标应用（例如 ``Jupyter Lab``）。
3. 卡片上如有 CPU/GPU/项目组选择，按任务需要调整（首次使用可直接
   使用默认值）。
4. 点击该卡片上的 ``启 动`` 按钮。
5. 等待几秒，**浏览器自动弹出新窗口**，新窗口中即为目标应用的交互
   界面（如 Jupyter Lab、Linux 远程桌面等）。
6. 在新窗口中正常操作即可。结束使用前，请在 ``应用列表`` 页对应卡
   片点击 ``关 闭`` 释放资源。

.. figure:: /_static/application-started.png
   :alt: 启动后弹出的新窗口
   :width: 90%

   点击 ``Jupyter Lab`` 卡片的 ``启 动`` 后浏览器自动弹出的 Jupyter
   Lab 界面。左侧是文件浏览器，右侧是 Notebook 工作区，可以新建文
   件、运行命令和编辑代码。

关闭应用流程
^^^^^^^^^^^^

1. 在 ``应用列表`` 页面找到对应应用卡片。
2. 点击卡片上的 ``关 闭`` 按钮。
3. 等待几秒，按钮恢复为 ``启 动``，对应作业状态变为 ``已关闭`` 或
   ``已完成``。

作业列表（应用启动后产生的作业）
"""""""""""""""""""""""""""""""""

``应用列表`` 页面底部的 ``作业列表`` 表格列包含：``作业ID``、``作业名称``、
``用户``、``分区``、``CPUS``、``GPUS``、``状态``、``耗时``、``节点数量``、
``操作``。

.. figure:: /_static/job-list.png
   :alt: 作业列表
   :width: 90%

   ``作业列表`` 显示当前用户的最近作业记录。

常见状态说明（仅解释普通用户最常见状态）：

- ``运行中``：作业正在执行。
- ``排队中``：作业等待资源。
- ``已完成``：作业执行结束。
- ``失败``：作业未成功。
- ``已取消``：作业被用户或管理员取消。

注意事项
^^^^^^^^

.. note::

   - 启动应用会占用集群资源。CPU、GPU 和项目组选择应与任务规模相匹
     配；不确定时使用默认或最小可用配置即可。
   - 使用结束后请主动 ``关 闭`` 应用，避免持续占用资源。
   - 关闭浏览器窗口不一定等同停止应用，必须回到 ``应用列表`` 页面点
     击 ``关 闭`` 才能释放资源（弹出的应用窗口是会话窗口，关闭后后
     端进程仍可能继续运行）。
   - 当前版本不再单独提供 ``批处理作业`` 标签；如需在后台运行脚
     本，请启动 Terminal/Jupyter 等应用后在其中执行。

常见问题
^^^^^^^^

- **应用点击 ``启 动`` 后没有弹出新窗口怎么办？**
  检查浏览器是否拦截了弹窗（通常浏览器地址栏右侧会有弹窗拦截提示，
  允许弹窗后再次点击 ``启 动``）。如已允许弹窗仍无反应，等待 10～
  30 秒后在 ``作业列表`` 中查看对应作业状态。

- **如何确认应用已经启动？**
  浏览器已弹出新窗口，且 ``应用列表`` 页面底部 ``作业列表`` 中对应
  作业状态为 ``运行中``。

- **为什么 Terminal 卡片没有 CPU/GPU 选项？**
  Terminal 直接挂接登录节点，无需申请额外资源。点击 ``启 动`` 后浏览
  器弹出新窗口即可使用。
